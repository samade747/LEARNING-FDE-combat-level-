# 04 — Ana Ka Blueprint Bhara Hua + Practice Exercise

## Ana Ka Monday Task, Cross Kiya Hua

Apna khud karne se pehle, dekho Ana ke Monday task ka blueprint kaisa dikhta hai — same 4 promotions,
bhare hue. Har line woh cheez hai jo usne do mahine se haath se already kar rahi thi.

- **Brief → Spec.** *"Har Monday, Support folder ke naye messages parho. Har ek ko exactly ek group
  mein dalo — complaint, question, order, ya other — aur ek one-page summary likho jisme har group ka
  count aur top 3 common complaints hon."* (Uske Gate 3 ki teen lines, hamesha ke liye likhi hui.)
- **Check → Eval.** *Barah purane messages jo usne already haath se sort kiye the, har ek apni sahi
  group ke sath saved.* Jab bhi woh worker ki instructions badalti hai, pehle in barah par test hota
  hai; agar ek se zyada galat sort hon, worker ko fix karti hai real mail chhune se pehle.
- **Aap → Exits.** *Agar message aisi language mein hai jo worker handle nahi karta, ya itni bari refund
  maangta hai jo Ana ne set ki limit se zyada ho, worker guess nahi karta — message flag kar deta hai
  aur Ana ko ping karta hai.* Baaki sab woh akela handle karta hai.
- **Session → Runtime.** *Worker har Monday subah ek chote always-on machine par chalta hai aur apni
  khud ki list rakhta hai ke kya process ho chuka hai* — Ana kuch nahi kholti, kuch yaad nahi rakhti.

Kuch bhi crossing wale din invent nahi hua. Yeh do mahine ke Mondays hain, permanent bane hue.

## Your Turn — Practice Exercise

Apna ek real task lo jo aap already agent se solve karte ho, same tareeqe se, ek se zyada baar. Isay
crossing ke teen steps se guzaro:

### Step 1 — Kya Yeh Proven Hai?

Pichli teen baar jab aap ne yeh kiya, kya same tareeqe se kiya? Agar method abhi bhi badalta hai, verdict
hai **NOT YET** — jab tak settle na ho jaye Mode 1 mein raho.

### Step 2 — Char Promotions, Har Ek Ek Line

- **Brief → Spec:** Worker ko chalane ke liye kya likhna parega?
- **Check → Eval:** 2-3 example inputs plus known-good answers jo isay test karein
- **Aap → Exits:** WOH ek specific case jahan worker ruk kar insaan ko bulaye — real escalation, "kabhi
  kabhi check kar loonga" nahi
- **Session → Runtime:** Yeh kahan rahega aapke bina chalne ke liye?

### Step 3 — The Fork

Worker kiske liye hai — sirf aap ke liye (personal harness) ya organization ke liye (Digital FTE)?

> **Grading focus:** Form aur concreteness par, is baat par nahi ke task acha hai ya nahi. Key tests:
> (a) kya task genuinely proven hai (same method kai baar) na ke jaldi cross kiya; (b) kya exit ek real,
> specific escalation case hai na ke skip kiya hua; (c) kya char promotions concrete hain, vague nahi.

Agar aap teenon steps bhar sako, aap "shayad kabhi agent banaunga" nahi soch rahe — aap ek ke liye
blueprint pakre hue ho. **Mode 2 track sirf char promotions hai, real mein kiya hua.**

## Yeh Aapko Kahan Le Jata Hai

Yeh crossing hai. Mode 1 labour-as-task tha — har baar ghante diye. Mode 2 labour-as-asset hai — ek
dafa banao, aur woh kaam kare jab aap sote hon. Ab aap **Mode 2 — Manufacturing** track mein enter karte
ho — ek blueprint ke sath, blank page ke sath nahi:

- **Python in the AI Era** — jis language mein manufacturing banti hai (aap direct karte ho; agent zyada
  tar likhta hai)
- **Build AI Agents** — worker jo loop chalata hai aur escalate karta hai
- **Eval-Driven Development** — eval jo isay grade karta hai
- **Building a Digital FTE** — chaaron promotions ek worker mein assemble
- **Deploy the Agent Harness** — runtime jispe woh rehta hai

Ek proven Mode 1 solution aur bhara hua blueprint le kar chalo — aap zero se shuru nahi kar rahe. Aap
kuch aisa promote kar rahe ho jo already kaam karta hai.
