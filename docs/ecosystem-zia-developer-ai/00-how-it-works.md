# 00 — Kaise Kaam Karta Hai: Decide, Build, Rhythm

## Decides, Then Builds

Zia Developer AI book ke decision gates chalata hai taake sahi shape choose ho, apni choice ka reason
cite karta hai, spec likhta hai, aur ek working, deployable agent scaffold karta hai — koi throwaway
skeleton nahi.

## Kabhi Bhi Gate Par Guess Nahi Karta

Jab aapki requirements kisi decision ko settle nahi karti, yeh ek hi sabse sharp sawal poochta hai aur
rukta hai. Spec-driven discipline, khud architecture choice par apply ki hui.

## Usi Agent Mein Jo Aap Already Use Karte Ho

Yeh Claude Code ya OpenCode mein ek marketplace se ek command mein install ho jata hai. Decision
knowledge ek portable skill hai, to yeh har host tak pohanchta hai — economy-tier models tak bhi.

## Usi Kunwein Se Grounded

Yeh wahi System of Record parhta hai jo Zia Tutor AI parhta hai. Har recommendation book mein grounded
hai, aur yeh **fail closed** hota hai — koi aisi architecture invent nahi karta jise cite na kar sake.

## Woh Rhythm Jo Yeh Enforce Karta Hai

Yeh book ka **10-80-10** rule hai, building par apply kiya hua:

- **Zia Developer AI** intent set karta hai — architecture decision aur spec, pehla 10%.
- **Aapka coding agent** build execute karta hai — 80%.
- **Aapka judgment** loop close karta hai — aakhri 10%.

Yeh Zia Tutor AI ka mirror hai: **wahi source, doosra host.** Jahan tutor method sikhata hai, wahan
developer usay chalata hai.

## Bade Ecosystem Mein Kahan Fit Hota Hai

[FDE AF Model](../ecosystem-fde-af-model/README.md) mein yeh **Layer 2** ka reference domain-builder
slot hai. Aage chal kar har vertical (accounting, sales, healthcare) apna khud ka domain builder banata
hai — usi Zia Developer AI pattern se, lekin apni domain ki architectures aur compliance constraints ke
saath preloaded. `/vsor` aur `/vtutor` jaise commands ([Ecosystem Concept](../ecosystem-ecosystem-concept/README.md)
chapter mein zikr hue) isi tarah kaam karte hain — sample repositories se shuru hote hain, blank folder
se nahi.
